## Behavior and boundary

React now uses real POST/GET/DELETE /api/session through the existing same-origin Workspace proxy. Startup, reload-style checks, focus, page-show, visibility return and hash navigation revalidate with the server. The selected custom request header and same-origin credentials are sent; no bearer token or client actor is created. Only exact successful Session objects are accepted. Unknown statuses, malformed output, redirects, network errors and the fixed ten-second request timeout leave unavailable state.

Session UI state lives only in memory. Credentials are read from the submitted form and the password field is immediately cleared; no localStorage/sessionStorage credential, token or identity cache is added. Checks, logout, expiry and dependency failure remove the authenticated subtree before awaiting results. A generation counter plus request cancellation prevents delayed headers or response-body completion from restoring an old identity. Events do not duplicate an already active session check or interrupt a mutation.

Successful login uses the server-confirmed session; invalid credentials show one generic message with focus moved to the feedback. Confirmed logout requires 204. Uncertain sign-in/sign-out does not claim success or automatically retry the mutation: the workspace is hidden and explicit session checking/sign-out is offered. Local expiry hides UI and asks for sign-in, without renewing in the background. The local clock can hide UI early; it never grants server access. PostgreSQL remains the server expiry authority.

The small session/current-workspace surfaces reuse the preserved prototype's soft-green colors, serif heading treatment and restrained controls. Username/password labels, autocomplete, native form submission, skip link, live feedback, visible focus and narrow-screen layout are present. Project/task/knowledge operations remain explicitly unimplemented. Signing in grants no project/document capability. The synthetic prototype, its data and assets remain unchanged. No new component, routing, auth or testing dependency is adopted.
