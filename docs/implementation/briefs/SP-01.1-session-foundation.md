## Contract-derived assertions

The contract is the source of route/schema/status names; PRD/UC supply behavioural obligations. Schema constraints alone do not prove HTTP handling. Proposed cookie/expiry choices below are explicitly distinguished from binding ACs.

| ID / evidence | Operation and case | Required assertion / source |
| --- | --- | --- |
| S01 / E-SCHEMA | `signIn`, POST `/session`, valid Login | `username` and `password` are nonempty strings; no email alias. A valid synthetic payload passes Login validation unchanged. Contract Login. |
| S02 / E-SCHEMA, E-HTTP | Missing/empty credential or extra `actor_id` | Login schema rejects invalid payloads without repairing them. Proposed HTTP adapter rejects with declared 400 rather than silently stripping fields; record this candidate setting and test actual handler behaviour. Contract Login/Error. |
| S03 / E-SESSION | Valid vs invalid credentials | Valid credentials alone create the session; wrong password/unknown account produce the same public 401 invalid-credential response and no new session. No assertion of identical wall-clock timing. AC-36, TC-01. |
| S04 / E-HTTP, E-SESSION | POST success | Declared 200 body conforms to Session (`user_id`, date-time `expires_at`, no extras). Proposed cookie attributes are verified separately; never include token/hash/password in body/logs. AC-01/36, ADR-0025 candidate. |
| S05 / E-SESSION | `getSession`, GET `/session`, missing/invalid token | Declared 401 Error, no protected result. A valid synthetic A token resolves to A; client selectors cannot establish B. AC-01/68. |
| S06 / E-SESSION | Idle/absolute expiry with injected clock | At or after effective expiry, GET returns 401; renewal cannot revive an expired token or extend absolute expiry. Production durations/renewal triggers remain D-02 choices. AC-68. |
| S07 / E-SESSION | `signOut`, DELETE `/session` | Declared 204, no body; old token then fails GET with 401. Repeat logout with expired/invalidated token still succeeds with 204. UC-01 EX-03, AC-37, TC-01. |
| S08 / E-SESSION | Logout races renewal | Control ordering at persistence boundary; after logout succeeds no later renewal of that token permits protected access. Include restart/persistent lookup; no in-memory-only proof. AC-37/68. |

Test real serializer output and ensure it cannot disclose seeded token/password fields; record whether invalid output fails or is safely projected under the chosen serializer. No schema-only HTTP pass. |
| S10 / E-DB | Same-client transaction and audit failure | Controlled rollback leaves no committed partial owned state; applicable minimum audit failure rolls back business state; client releases on success/failure and rollback failure discards suspect connection. ## Evidence sequence

1. **E-SCHEMA:** reuse the installed contract loader and contract tests. Record Node and installed Ajv/formats versions, source hashes and actual assertions. This is structural pre-evidence, not Fastify/provider/permission evidence.
2. **E-HTTP:** in the isolated spike, pin actual Fastify/compiler/plugin candidates and exercise the actual HTTP adapter, request validation and response serialization together. Test non-mutating validation deliberately; do not assume Fastify defaults match the contract harness. Include HTTPS cookie observations.
3. **E-DB / E-SESSION:** use actual pg and isolated PostgreSQL persistence with deterministic clock and controlled interleavings. Test KDF/cookie/session behaviour without logging secret values. Record schema changes as disposable probe schema only, not application migrations.
4. Record failed attempts and Not run cases. Submit recommendation, alternatives and unresolved expiry/provisioning/CSRF/dependency choices to the owner. Only an actual recorded decision can change ADR status or authorise application integration.
