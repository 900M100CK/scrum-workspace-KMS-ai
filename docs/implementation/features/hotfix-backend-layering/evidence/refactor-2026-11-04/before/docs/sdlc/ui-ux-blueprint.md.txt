### 1.2 Boundaries

```mermaid
flowchart TB
    Browser["Browser presentation UI - apps/web"]
    subgraph Workspace["Workspace service"]
        GW["Authenticated gateway / session context"]
        Work["Projects, Scrum and permission authority"]
        Relay["Guarded provider relay"]
    end
    subgraph Knowledge["Knowledge service"]
        Docs["Immutable documents and versions"]
        Evidence["Keyword/vector retrieval, evidence and citation validation"]
    end
    Provider["Unselected embedding / generation provider"]
    Browser -->|Authenticated public contracts| GW
    GW --> Work
    GW -->|Authenticated internal calls| Docs
    GW -->|Authenticated internal calls| Evidence
    Evidence -.->|Prepared evidence and protected handoff coordination| Relay
    Relay -->|Guarded exact payload transport| Provider
```

Workspace owns permission decisions and provider transport; Knowledge owns documents, retrieval, answer preparation and provenance. Each service writes only its own database. Browser access to Knowledge public paths is proxied/guarded through Workspace; there is no browser/provider or database connection. Internal identity and actor context require service authentication, not an assumed trusted loopback network. Generation waiting is outside the handoff guard. Full evidence-set access/validity checks and frozen-byte handoffs are server responsibilities; UI visibility is not enforcement.

PostgreSQL/pgvector storage is selected under ADR-0004. Application framework, rendering model, identity mechanism, provider and hosting remain open decisions; SAD ports/topology are candidates. Proposed ADR-0018–ADR-0023 supply draft mechanisms, not accepted implementation authority. The v1.1 gateway and canonical sitemap corrections are retained.

### 1.3 Constraints and assumptions

- One student implements the capstone over a relative five-month plan; submission April 2027. Kickoff, weekly capacity and feasibility remain unmeasured. Product actors remain a team with scoped capabilities.
- Retain the original 60 release Must. FR-27/49/62/70 are Should, FR-64–67 Could, FR-35 outside this release, FR-45 Withdrawn. Enhanced reports and Future Work remain excluded.
- Runtime AI is read-only; authorised humans use normal mutations. No saved conversations/answer store, global user directory, role editor, new service or automatic runtime agent is added.
- Provider failure leaves work, documents and keyword operations usable while their own services/current authority are healthy. Knowledge failure affects docs/search; Workspace/authority failure denies affected protected operations. Semantic readiness is separate from keyword availability.
- Desktop-first layouts and smaller inspection viewports are candidates. Browser/device targets, numeric timing/resource/target-size budgets and visual acceptance remain open in WF-09. Previous unvalidated numeric budgets are withdrawn.

## 3. Design views

### 3.1 Composition view

Symbolic modules describe responsibilities, not an adopted UI framework/component library.

| Module | Responsibility | Declared operations |
| --- | --- | --- |
| Auth/shell | Session, project context and clearing protected display | signIn, signOut, getSession, listProjects, getAllowedActions |
| Projects/members | Capability-gated creation and membership; no role editor | createProject, getProject, listMembers, addMember, removeMember; optional editProject |
| Backlog/Sprint planning | Work creation/order, fixed lifecycle, independent allocation outcomes | createTask, listTasks, reorderBacklog, createSprint, listSprints, getSprint, listSprintItems, allocateTask, startSprint, completeSprint |
| Board/task | Direct states, assignee, ordered blockers and current placement | getTask, editTask, setTaskState, setAssignee, listBlockerEvents, recordBlocker |
| Documents/history | Read-filtered list, creation, exact versions and readiness | listDocuments, createDocument, getDocument, listVersions, getVersion, getReadiness |
| Independent access/actions | Known-ID policy or non-reading command surface | getDocumentPolicy, listDocumentReadGrants, setClassification, grantDocumentRead, revokeDocumentRead, getAllowedActions, getDocumentCommandPrecondition, reviseDocument, archiveVersion, deleteDocument; optional editDocumentMetadata |
| Search/relationships | Permitted document keyword search and explicit links | keywordSearch, listLinks, createLink; optional searchTasks/removeLink |
| AI/citation inspector | Buffered answer and both citation kinds | askQuestion, openCitation, getVersion; renewed getProject/getSprint/getTask |
| Audit/trace | Separate audit, trace and optional summary authorities | listAudit, getTrace; optional getRetrievalSummary |

Multi-select Sprint allocation is one allocateTask request/key/result per task, not a bulk transaction (ADR-0014). First human work/document journeys precede AI. Keep fixed Planned → Active → Completed Sprint lifecycle, one Active Sprint/project and direct task state transitions.

### 3.4 Interaction view

#### 3.4.1 Work mutation

```mermaid
sequenceDiagram
    actor Member
    participant UI as Board
    participant GW as Workspace gateway
    Member->>UI: Choose Done with pointer or keyboard
    UI->>UI: Mark pending and preserve original key/payload
    UI->>GW: POST /tasks/{task_id}/state with state=done and expected_revision
    alt Confirmed commit
        GW-->>UI: 200 Task with revision
        UI-->>Member: Confirm result and renew permitted placement
    else Stale request rejected
        GW-->>UI: 409 Conflict
        UI-->>Member: Reload permitted state and reconsider
    else Response lost
        UI-->>Member: Outcome unknown - no fresh-key replay
    end
```

getTask is GET /tasks/{task_id}. setTaskState accepts todo/in_progress/done, not display labels. Reopening work from a Completed Sprint preserves completion history and returns it to Backlog in To Do; it does not reopen the Sprint. Member removal/rejoin never restores former restricted grants or delegated capabilities. Membership removal guards the last effective membership manager and invalidates grants/current assignees transactionally under existing policy.

#### 3.4.2 Buffered AI and document citation

```mermaid
sequenceDiagram
    actor Member
    participant UI as Drawer and inspector
    participant GW as Workspace gateway
    participant KN as Knowledge
    Member->>UI: Submit one question
    UI->>GW: POST /knowledge/questions
    GW->>KN: Authenticated scoped question
    Note over GW,KN: Persist exact manifests and validate whole evidence set before guarded delivery
    KN-->>GW: Validated result or declared failure
    GW-->>UI: Buffered permitted result or error
    Member->>UI: Open document citation
    UI->>GW: GET /knowledge/citations/{document_id}/{version_id}/{passage_id}
    GW->>KN: Renew current scope for exact locator
    KN-->>GW: Permitted passage or declared error
    GW-->>UI: Passage/version or generic error
```

Before provider input and answer delivery, server guards check the entire evidence set including uncited context, exact committed manifests/bytes, current access and validity. Invalid/revoked evidence withholds the original draft; removing chips/sentences is insufficient. Client validation cannot replace these checks. getVersion is a separate exact-version read; never substitute Current or invented offsets. Verified unavailable identity requires ADR-0013's surviving read policy, exposes no excerpt, and otherwise returns the same generic 404.

#### 3.4.3 Operational observation

Preserve delivered operational locator/time/revision only as ephemeral answer context. Renew getProject/getSprint/getTask to show permitted current state with a separate label. Reload/direct navigation without that context shows **Original observation unavailable**. URL/current values/browser storage cannot recreate authoritative history; no saved-answer/status endpoint is added.

Unknown and inaccessible reads return identical 404 `{"code":"not_found","message":"Resource unavailable"}`. Do not distinguish hidden existence or revocation cause. Clear protected output on expiry, denial or unknown authority; authority/dependency failure is not empty success. Already delivered information cannot be recalled. A 403 action denial is applicable only where the contract permits it for a known readable resource; never use it to distinguish an inaccessible read.

| State | Lifetime / constraints |
| --- | --- |
| Authenticated session | Mechanism remains OD-09; server identity authoritative; clear protected display/actions on sign-out/expiry/lost scope |
| Route/filter selectors | URLs select resources/views, never confer authority or reconstruct observations |
| Safe user-entered drafts | Ephemeral local form state; never refill protected old content after revocation |
| Preconditions | Opaque precondition_token binds actor/session/project/action/document/known version; consumed on commit, grants neither read nor action authority |
| Answer/observation | Ephemeral view memory only; no persisted answer/history feature |
| Operation identity | Preserve original scoped key/payload for reconciliation where available; lost context leaves explicit uncertainty |

| Operation | Exact wire constraints |
| --- | --- |
| createTask | Required type=story/task/bug and nonempty title; optional description. No priority field, UUID requirement or invented length maximum; use setAssignee separately. |
| setTaskState | state=todo/in_progress/done and numeric expected_revision, with scoped Idempotency-Key |
| reorderBacklog | Full unique task_ids and decimal-string expected_revision; ReorderResult returns project_id/backlog_revision |

OpenAPI controls required fields, additionalProperties, headers, exact error unions and bounds. Non-reading commands cannot prefill hidden title/content/history/current pointer; acquire only the selected action's precondition. After 409 reconsider the command with renewed permitted data/preconditions. Timeout is unknown, not proof of rollback; preserve the original identity/payload rather than obtain a fresh token/key and blindly resubmit.

### 3.7 State dynamics view

#### 3.7.1 AI results

```mermaid
stateDiagram-v2
    [*] --> Idle
    Idle --> Loading: Deliberate submit
    Loading --> Answered: HTTP 200 answered
    Loading --> Partial: HTTP 200 partially_answered
    Loading --> Insufficient: HTTP 200 insufficient_evidence
    Loading --> Conflict: HTTP 200 conflict
    Loading --> Withheld: HTTP 503 answer_withheld
    Loading --> DependencyFailure: Declared dependency error
    Loading --> UnknownOutcome: Response lost or timeout
    Withheld --> Idle: Deliberate new question
    DependencyFailure --> Idle: Deliberate retry
    UnknownOutcome --> Idle: Explicit new intent subject to server quarantine
```

Partial contains supported claims/citations and explicit missing_components without hidden-source hints. Conflict is a 200 answer category, distinct from stale mutation 409. Withheld contains exactly code answer_withheld and message Unable to provide this answer; no generated text, run/source IDs or detailed cause. Other declared failures contain no draft. No automatic resend after unknown responses; new user intent cannot override server quarantine. A stale health badge cannot permanently disable the editor. Closing citation inspection restores its original result category/focus.

#### 3.7.2 Version lifecycle

```mermaid
stateDiagram-v2
    [*] --> Current: First save commits
    Current --> Superseded: New immutable Current revision commits atomically
    Current --> Archived: Authorised archive
    Superseded --> Archived: Authorised archive
```

This models one immutable version; revision creates a different Current version and preserves old locators. No product Draft, publish or restore operation exists. Document deletion is independently authorised and does not require an already Archived version. Exact unavailable-locator policy follows ADR-0013; physical retention remains OD-04. Semantic readiness pending/ready/failed is orthogonal. Ordinary retrieval uses permitted Current; history is explicit and labelled.

### 3.8 Algorithm view

#### 3.8.1 Full Backlog reorder (Proposed ADR-0018)

1. Gather all listTasks(location=backlog) pages through next_cursor=null at one backlog_revision string. Reject filtered subsets; paging 409 discards the accumulated generation.
2. Enable reorder only when complete and current scoped discovery includes reorderBacklog. Check equal length, uniqueness and exact set equality locally; server remains authoritative.
3. Preserve scoped Idempotency-Key and payload `{task_ids: fullPermutation, expected_revision: capturedBacklogRevision}`. POST /projects/{project_id}/backlog-order.
4. On 200 acknowledge ReorderResult then renew permitted current state. A replay receipt may describe an earlier commit; response.backlog_revision is not proof of the current snapshot. Never assume +1.
5. On 409 discard stale pages/order, reload and require reconsideration. No automatic reapplication.
6. On lost response show Outcome unknown; reconcile the same original key/payload if available. No fresh-key blind retry, inferred rollback or invented status endpoint. Lost context retains uncertainty.
7. Clear protected rows/actions on expiry, denial or unknown authority. Dependency failure differs from empty success. WF-02/BL-01–10 specify frame variants.

#### 3.8.2 Metrics

For each permitted metric independently: measured zero renders 0 ms/0 tokens; unavailable renders Not measured; not_performed renders Not performed. Preserve each metric's actual unit and stage/status. Failed execution may have measured duration. Scope/dependency failure clears protected output and renders generic failure, not empty success or zero. Do not expose hidden rank gaps/counts; structure validation does not establish claim support (Proposed ADR-0021).
