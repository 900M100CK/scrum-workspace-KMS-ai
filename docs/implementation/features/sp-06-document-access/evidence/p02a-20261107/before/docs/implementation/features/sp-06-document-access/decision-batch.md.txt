## Concrete behavior for owner review

An operator grants document creation to a particular current member; an Admin label alone does nothing. Creating restricted content gives that author a revocable read grant plus the already-settled independent document command capabilities. After the author revokes their own read, the explorer/detail reveals no title/content/owner/version/readiness, but a known-ID access-management page can still show the minimal policy and current grantees under retained manage-access. A current reader without manage-access cannot inspect that page.

If revocation races an already-running protected response, the server waits for its send to finish or definitively abort before reporting successful revocation. A response that has aborted cannot later continue. The server cannot recall bytes already sent. If authority, a required service check or restart state is unknown, it sends no protected output. Indexing/provider availability does not grant access or block ordinary healthy work; no AI/provider is introduced here.

Creation registers identity/policy first, then immutable content under the same identity/key/payload. A connection loss is an unknown result; retry/reconciliation preserves that identity. Retain policy-only orphans until safe cleanup is separately designed. Content-bearing original201 Document response conflicts with a revoked-author read on replay unless revalidated; P02 must specify the fail-closed status/body within existing independent-rights rules before implementation, not invent a new metadata-bearing receipt.
