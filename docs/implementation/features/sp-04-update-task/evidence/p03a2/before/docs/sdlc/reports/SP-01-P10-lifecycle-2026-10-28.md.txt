## Outcome

GET /session now renews only an enabled, strictly unexpired current session. PostgreSQL time is sampled after clock/account/session locks; equality at idle or absolute expiry denies. The new effective deadline is the lesser of immutable absolute expiry and the greater of existing expiry and DB now plus configured idle duration. Only a real extension increments revision and writes session_renewed audit. Successful GET refreshes the same secure host cookie using DB-derived Expires, without app-clock Max-Age authorization or token rotation.

DELETE /session validates exact configured Origin and X-SACW-Request: 1, rejects bodies, and atomically revokes the current token with session_revoked audit. Confirmed commit returns empty 204 and clears the matching Secure/HttpOnly/SameSite=Strict/Path=/ host cookie. Missing, malformed, unknown, expired and already revoked tokens are idempotent. Independent concurrent sessions remain valid. Clock fault does not prevent reducing access by revocation, and logout cannot restore clock health. Missing/unreadable clock state for a known session denies.

Audit failure rolls back mutation. An error receiving COMMIT acknowledgement is an unknown outcome: 503, no success cookie or cookie clearing, no automatic retry. A later explicit logout is idempotent. Invalid final GET output is withheld rather than projected; the final onSend hook suppresses queued cookie output on unsuccessful session responses.

Migration 006 only widens the existing audit action constraint. Empty reverse/forward/repeat succeeds; reverse refuses retained lifecycle audit without deletion. Migrations 001–005 remain unchanged in this task. Existing storage expectations now count six Workspace migrations (four retained after the targeted older policy rollback); P08 empty rollback first removes 006 before 005. These are inventory/order changes, with existing behavior assertions retained. Workspace contract v0.2.10 documents the existing lifecycle operations and DELETE 413/415 transport responses; no new operation or dependency is introduced.

## Limits and handoff

These checks serialize session decisions; they do not hold a guard through HTTP delivery. A response authorized before logout may already be in flight after logout commits. Subsequent session checks after confirmed logout deny the old token; this is not D-07 source-revocation or protected-content handoff evidence. Later project/document operations still require their own current authority checks.

The singleton clock row serializes short session transactions and is bounded by existing lock/statement timeouts; no lock spans provider or network waits. Deployment throughput/calibration remains open. Observed clock regression latches failure, but entirely unobserved elapsed time during idle/outage/restart remains unprovable. Secure cookie wire observations do not establish browser storage/send behavior.
