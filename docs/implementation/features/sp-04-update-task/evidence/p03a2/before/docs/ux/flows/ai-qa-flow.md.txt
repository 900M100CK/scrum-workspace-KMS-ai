## 1. Request and protected handoffs

Use the authenticated application session, not client-asserted user identity or an assumed JWT. Submit `POST /knowledge/questions` with project selector, question and explicit current/historical scope. All paths here are OpenAPI keys relative to `/api`.

1. Workspace checks current session and membership; Knowledge retrieves only authorised project AND document scope. Project-shared sources need no explicit grant; restricted sources do, including the author's revocable grant. Unknown authority denies. Default retrieval is Current-only; deliberate history is labelled. Revisions become Current immediately; no product Draft exists.
2. Persist the frozen payload's complete immutable manifest outside the guard. After durable acknowledgement, Workspace revalidates current scope while Knowledge validates evidence/revisions/availability and exact payload binding, under the guard through provider transport handoff completion/abort. A mismatch sends no bytes and releases the guard before a bounded fresh manifest/attempt.
3. Generation waits outside the guard. Buffer all output. A loading indicator exposes no answer tokens, source titles, snippets or hidden counts.
4. Validate citation identities assigned from server evidence records. Before answer delivery, persist a fresh complete manifest outside the guard, then revalidate exact manifest/payload binding and the **entire evidence set, including uncited model context**, session, permissions and validity under the guard through response transport handoff.
5. If any evidence was revoked, withhold the entire original draft. Optionally regenerate as a new bounded attempt solely from remaining permitted evidence and repeat both handoff checks. Never remove only a citation/sentence and release the old text.
6. Opening a citation performs a new protected read with current checks; previous delivery grants no lasting authority.

Current task/Sprint answers use authorised operational observations with entity identity and observation time/version. Recorded facts, synthesis and uncertainty remain distinct. Conflicting accessible evidence is surfaced with exact citations; nonempty but inadequate evidence still gives insufficient evidence. Runtime AI remains read-only; retrieved text cannot grant authority.

## 2. Answer and source inspector

The following is a **layout placeholder, not a source quotation, project fact or evaluation fixture**:

```text
Question: <user question>
Recorded fact: <claim supported by an accessible evidence passage> [1]
Synthesis: <supported interpretation, labelled as synthesis>
Uncertainty: <what the evidence does not establish>
[1] <permitted source title> · <exact version_id> · <passage_id>
```

Branch on the server-supplied citation `kind`. For `document`, use `GET /knowledge/citations/{document_id}/{version_id}/{passage_id}`. Display only the returned permitted title, exact immutable identity, excerpt and Current/Superseded/Archived validity label. Do not invent a JWT quotation, classification or version. The Passage contract does not include classification; displaying it needs a separate authorised metadata response.

For document citations, “Open full document” opens the exact version after a fresh check; editing controls additionally require content-write authority. No automatic redirect to Current.

| Inspector result | UI behaviour |
| --- | --- |
| Exact accessible passage | Show exact excerpt and version/validity; historical content is clearly labelled. |
| Unknown or inaccessible source | Generic `404` / “Source unavailable”, identical for both; no title, version, snippet or revocation explanation. |
| Evidence unavailable, surviving identity readable | “Citation unavailable”; no version substitution. ADR-0013 and UnavailableCitation permit only a verified surviving locator after current membership and retained read-policy checks; no excerpt or newer-version substitution. |
| Authority unavailable | Generic service failure; withhold protected source details. |
| Session expired | Sign-in required; no protected response. |

### Operational citation branch

For kind=operational, keep entity_kind, entity_id, observation_revision and observed_at from the delivered citation as the cited observation locator. Never call the document passage endpoint or fabricate a document/version/passage tuple. The inspector uses current project context and a fresh authorised getProject/getSprint/getTask according to entity_kind, verifying the returned project/identity. Display the cited observation time/revision separately from “Current state, read now” and its current entity revision. These revision domains are distinct; do not compare them as interchangeable counters.

If a task changes from Blocked to Resolved after the answer, keep the cited observation label historical and show the fresh resolved state separately. OperationalCitation contains no historical snapshot body; do not reconstruct one from current values or a text index. No historical-snapshot endpoint is implied. Unknown/denied current entity gives generic 404 without exposing protected cached titles/values; dependency failure shows generic unavailable rather than substituting old state as current. Already delivered answer bytes cannot be recalled. Browser route /p/:projectId/observations/:entityKind/:entityId is an inspector proposal backed by existing reads, not a new HTTP operation.

### Direct navigation and reload without the original observation

The browser route identifies a current entity, not a retrievable historical observation. On reload, direct navigation or lost in-memory answer context, show “Original cited observation unavailable in this view” instead of a historical observation panel. Do not reconstruct observed_at/observation_revision from the current entity, clock, URL query values, browser storage or a model answer. A separately renewed permitted getProject/getSprint/getTask may still show “Current state, read now”; a current read does not recover the cited snapshot. If current access fails, clear protected details and use the existing generic denial/failure state.

Only render the cited locator when it comes from the actual delivered server citation in the current answer context; it is not a durable saved-answer feature or an access grant. Browser Back may preserve that in-memory context while available, but must still renew current scope. A missing original context offers a return to an available answer, or a deliberate new question, without automatically resubmitting. No summary/trace entitlement or history endpoint is inferred to fill the gap.

## 3. Question states and actions

| State | Message / available actions |
| --- | --- |
| Loading / final validation | “Preparing answer…”; no streamed draft output. |
| Original answer withheld / bounded regeneration | “Unable to deliver this answer. Please try again.” or “Preparing answer…” during the new attempt. Do not name the revoked source or expose the internal cause. |
| Insufficient evidence | Contract message: **“Insufficient evidence”**. Optional UI guidance: “Try another question or search by keywords.” Do not list hidden/restricted/Draft sources as possible reasons, counts or hints. |
| Conflict | Show unresolved conflicting permitted evidence; do not claim newest means correct. |
| AI dependency failure | Explicit failure, with no generated answer; offer keyword search and normal work/document UI where their dependencies are available. |

“Create New Document” appears only with current create capability; the creation server rechecks it. The runtime AI does not create documents. Keyword search uses `POST /knowledge/search/keyword` with current scope checks.

Withholding/regeneration are interaction states, not new QuestionResult enum values. The current contract defines answered, partially_answered, insufficient_evidence and conflict, plus HTTP errors. ADR-0013 and Knowledge OpenAPI v0.2.2 map terminal withholding to HTTP 503 AnswerWithheld with a fixed generic message and no evidence or source identities. Do not use insufficient evidence to disguise infrastructure failure.

## 4. Failure boundaries

| Failure | Required behaviour |
| --- | --- |
| Generation/embedding/semantic dependency fails or budget is exhausted | FR-69: explicit AI failure. FR-33/FR-34: work, permitted document reads and keyword retrieval continue when Workspace/Knowledge and their required stores remain available. |
| Knowledge service/storage fails | Document reads and keyword search may also fail; show their unavailable state. Keep Workspace work operations available when their own dependencies are healthy. |
| Workspace/session/permission authority fails | Deny protected output; no unrestricted search, cached answer or source fallback. |
| Network outcome uncertain | Show unavailable/retry guidance, recheck scope on retry; no availability percentage promise. |

## NEXT-04 deliberate retry and recovery

Provider health is an advisory badge. With a valid session and no confirmed scope denial, keep the question editor/new-request action reachable after an AI failure; a single request remains in flight at a time. A terminal explicit failure/AnswerWithheld offers deliberate “Try again” as a new request with renewed scope and fresh run/attempt manifests; it never releases the original draft or resumes an old protected handoff. Server configuration bounds retries; the browser does not loop or repeat on a timer.

For a lost response, show “Previous request outcome unknown” and stop automatic retries. Offer keyword search and, if the user deliberately chooses it, “Submit as a new question”, with notice that the previous request may have completed. This is new user intent, not transparent replay or a claim of rollback; unresolved server transport quarantine may still reject it. A later successful request clears the stale failure badge. Session expiry requires sign-in; confirmed membership loss clears protected state. Current authority/dependency errors remain server decisions, not health-badge guesses.

Keyword and document/work actions depend on their own services. Semantic/provider failure does not disable healthy keyword search. Knowledge failure can disable document search/reads while healthy Workspace work remains available. No health polling, request-status endpoint, provider switch or runtime AI mutation is introduced.
