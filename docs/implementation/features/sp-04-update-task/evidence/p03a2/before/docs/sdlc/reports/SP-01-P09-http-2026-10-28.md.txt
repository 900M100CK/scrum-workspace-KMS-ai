## Outcome and evidence

POST /session verifies pre-provisioned credentials and issues a fresh secure cookie only after known database commit. GET /session derives request-local context from that cookie and current P08 state; client actor/service/header/query values grant no identity. Current disabled/revoked/expired/unknown state denies. GET does not renew and DELETE remains unimplemented in this slice. No UI was changed and no project/document capability is conferred.

Actual application handlers use exact Workspace dependencies: @fastify/cookie 11.1.5, Ajv 8.20.0 and ajv-formats 3.0.1. The application reads the actual versioned contract artifact; it imports no development-only schema harness. Non-mutating request validation rejects extras/type coercion. Final response-object validation occurs at serialization after mutable preSerialization hooks, with no silent projection of invalid objects. Unsuccessful login also strips queued cookie output in onSend after the cookie plugin flushes it.

Selected cookie: __Host-sacw-session, Secure/HttpOnly/SameSite=Strict/Path=/, no Domain and DB-derived Expires. No app-clock Max-Age calculation is used. Session JSON contains only user_id/expires_at; Error has the declared enum/message/run_id shape. Exact configured HTTPS Origin plus X-SACW-Request: 1 is required for login; all session responses use no-store. Wrong/unknown/disabled failures are generic with real/dummy KDF work; DB/clock/audit/KDF-capacity/internal errors expose only generic unavailable responses.

Explicit runtime DB/origin configuration wires the real server; missing configuration leaves sessions unavailable, partial/invalid configuration stops startup, and runtime rejects operator/Knowledge identities. No automatic provisioning, time initialization or migration runs. Liveness remains independent. [SESSION-HTTP.md](../../../services/workspace/SESSION-HTTP.md) documents startup and runtime packaging of the contract.

## Corrections and compatibility

Exploratory tests first found that a preSerialization validator could run before a later payload mutation, and the normal serializer would silently drop the extra field. Moving validation into the final serializer made invalid output fail, then a second negative exposed the cookie plugin's queued onSend output surviving an earlier header removal. The final onSend suppression now prevents a success cookie on unsuccessful POST; the same negative passes. One exploratory failing assertion displayed a short-lived synthetic test cookie; assertions were changed to compare booleans without printing cookie values, and that disposable DB was removed. No such value is retained in the final run. Those console-only exploratory attempts lack complete source snapshots and are not presented as reproducible measured runs.

TypeScript checks also caught CJS format-plugin interop and unknown error typing. A typed createRequire bridge and explicit error narrowing fixed those without disabling type checking or weakening schema constraints. Captured logger serializers omit URL/query, headers/body/cookies and internal causes; normal/error canaries are checked against actual logs. Default logging stays disabled.

Workspace v0.2.9 synchronizes the stale cookie scheme name to the selected host cookie and declares POST 413/415 transport errors at the 8192-byte JSON limit. No operation/FR is added; Knowledge wire behavior is unchanged. The compiled-layout test confirms the contract artifact path, but deployment must retain that artifact layout explicitly.

An output/receipt failure after commit can leave an inaccessible retained session row; it is not automatically retried or purged. Expires header observation is not browser storage/send proof. The shared libuv/KDF deployment and unobserved-clock limits from P08 remain open. Request-local session identity does not implement D-07 or replace later current project/document checks.
