## Change and authority

The owner selected pre-provisioned username accounts, opaque digest-backed independent sessions, same-origin secure cookie with Origin/header checks, and configurable starting idle 30 minutes / absolute 8 hours. The later owner instruction explicitly permits P07 to add only scaffold/interfaces and local HTTPS, with no concrete KDF/time algorithm or schema extension. These are configuration starting points, not a risk-analysis conclusion. Account lock/disable policy is still unselected; TC-01 remains binding.

Workspace now has `SessionClock` and `PasswordVerifier` ports and an independent `readSessionPolicy` configuration reader. The ports have no runtime adapter; the reader is not connected to an unimplemented handler. It accepts overrides and rejects invalid/unsafe durations or idle greater than absolute. No crypto, pg, production clock-health logic or new migration was added to the application.

The existing Vite foundation now optionally reads server-only TLS key/certificate paths from SACW_DEV_TLS_KEY / SACW_DEV_TLS_CERT. Both must be set together; unreadable inputs fail explicitly. The `/api` proxy strips the contract server base and sends to the fixed loopback Workspace target. Regex prefix matching avoids treating `/apievil` as API. No Knowledge browser target or permissive credentialed CORS was added. Vite's installed secret-deny patterns are retained, including credential/config/certificate formats, and `.tmp` is denied. Keys stay ignored; no CA was installed into OS/browser trust.

The [local HTTPS guide](../../../apps/web/LOCAL-HTTPS.md) explains generation, start commands, explicit trust, browser limits and the difference between plain scaffold mode and HTTPS cookie integration. Existing prototype/design is unchanged.
