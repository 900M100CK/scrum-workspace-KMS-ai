### P1-R01 — Blocking for handler readiness: current location is still an unfulfilled Stage 4 dependency

This is a confirmation of the queue's existing gap, not a newly discovered defect. [ADR-0018](../../adr/0018-operational-read-projections.md) requires a persisted current-location discriminator and applicable Sprint reference. The [logical model](../../../contracts/data-model.json), Task entity, does not yet describe that representation or its invariants. [DATA-04](../data-design.md) does not yet map the new read projection, and the applied Workspace task schema contains position/state/revision but no explicit current-location marker. [DATA-FIT-01](../data-policy-fit-review.md), completed-Sprint reopening row, still suggests deriving Backlog from current state/allocation without the newer distinction.

The counterexample remains: complete task in Sprint A → reopen into Backlog/To Do → mark Done in Backlog while keeping A's completed association. Historical completion plus current Done cannot identify whether the task currently belongs to Backlog or retained completed work. The draft `work_location` contract correctly distinguishes these cases, but a schema field in a response does not supply the persisted truth.

**Owner / closure:** Stage 4, then Stage 5/8. Define the marker, same-project references, valid location/state/allocation combinations, revision changes and atomic mutation rules; reconcile DATA-FIT-01 and the logical/physical diagrams. Before handlers, supply an additive migration with an explicit existing-data reconciliation rule; preserve applied migrations. Extend the reconstruction assertions with the full reopen-then-Done-in-Backlog cycle, later allocation to another Sprint, and rollback. Trace: FR-07/09/42; NFR-04; SC-01/03; TC-07/16/21.

### P1-R02 — Important: Backlog reorder has no defined read-to-write concurrency contract

The [Workspace contract](../../../contracts/openapi/workspace.openapi.json), `POST /projects/{project_id}/backlog-order` / `Reorder`, requires `task_ids` and `expected_revision`, but does not identify which aggregate revision is compared or which public read supplies it. `listTasks` returns items and a cursor; task revisions, Project revision and the opaque cursor dataset version are distinct candidates, with no specified mapping. This finding does not assume a new revision field or endpoint is necessary; an explicit mapping is necessary.

The same operation does not say whether `task_ids` is the complete ordered Backlog or a subset, what happens to omitted items, or how items allocated between reading and submitting affect the request. New pagination makes this consequential: a user reorders a visible page while another user allocates an item or changes order. Merely declaring a 409 response does not specify the stale-state comparison or the resulting complete order. PRD AC-41 and VERIFY-01 describe the outcome, not these protocol semantics.

**Owner / closure:** Stage 5 with Stage 4/6/8. Define the revision source and every mutation that invalidates it; define full-list versus partial-list semantics, omission/duplicate/out-of-scope handling, empty input, deterministic resulting order and same-key replay. A fresh client must obtain every precondition through documented reads and reject a stale reorder without overwriting newer ordering. Include a paginated fixture, concurrent allocation/reorder and renewed-read assertion. Trace: FR-41; NFR-02/04; BR-02/03; SP-05; TC-07/19/21. This is an additional detail under SYS-02, not an added business feature or release requirement.

### P2-R01 — Important: version action scope has no unambiguous complete locator

**Evidence:** [Workspace OpenAPI](../../../contracts/openapi/workspace.openapi.json), `getAllowedActions`, accepts `resource_kind=version`, `project_id` and one `resource_id`; ADR-0019 says to resolve the version's actual parent, but neither specifies a composite resource-ID encoding nor supplies document_id. [DATA-04](../data-design.md), DocumentVersion identity, and [Knowledge migration 001](../../../services/knowledge/migrations/001-store.up.sql), `document_version`, use `(document_id, version_id)` as the key. No global uniqueness constraint or documented global version-ID invariant resolves the missing component. `listVersions` and `getVersion` already preserve both components.

**Consequence:** Two documents in the same project may have the same version_id under the declared data contract. The new request cannot distinguish them as currently specified. Choosing the first match, using a readable match as authority for a different version, or relying on accidental UUID uniqueness is not an exact-scope protocol. This is a design ambiguity, not an observed permission leak.

**Correction owner / closure:** Stage 3/5 with Stage 4/6/8. Specify document_id plus version_id, a formally defined composite locator, or an explicitly enforced equivalent identity. Bind the response and parent-document permission checks to that same identity. Test two documents with equal version IDs and different permissions, mismatched project/parent selectors, unknown versions and independently authorised non-read actions. Update ADR-0019, SP-07 and the consumer examples together. Trace: BR-05/10; FR-04/12/47/59; SC-05/06.

### P2-R02 — Important: run discovery conflates summary access with full trace access

**Evidence:** Workspace `getAllowedActions` says `run requires scoped trace access`; [ADR-0019](../../adr/0019-scoped-ui-discovery.md) likewise groups run trace/summary under trace-read. Its allowed-operation catalogue includes `getRetrievalSummary`. [PRD FR-27 / AC-27](../PRD_SRS.md#44-evidence-backed-ai-and-current-state) permits an authorised answer reader to inspect the bounded summary, while FR-58 requires trace-read for full trace inspection. UC-13 Alt-1 preserves this distinction. UI guidance enables controls only from returned allowed actions.

**Consequence:** An answer reader entitled to a delivered FR-27 summary but lacking trace-read receives denial during run action discovery and cannot enable that summary control. Requiring a full-trace grant would silently strengthen the summary's access prerequisite. FR-27 remains Should; this finding applies when that optional operation is delivered and does not block unrelated member/document lists.

**Correction owner / closure:** Stage 3/5/6 with SP-13 and Stage 8. Evaluate summary and trace entitlements separately at run scope; return only each permitted operation and apply separate source checks. Do not broaden full-trace access or promote FR-27 into Must. Add paired cases for an answer reader without trace-read, a scoped execution inspector, an unrelated member and a revoked reader. Trace: BR-10/12; FR-27/58/59; SC-06.
