## Findings that affect implementation

1. Actual Fastify defaults accepted valid username/password with extra actor/email fields and coerced a single-element username array. Explicit non-mutating Ajv validation rejected them. Missing required username still failed with the baseline. The existing schema harness alone would not establish this runtime behaviour.
2. Response serialization projected extra secret fields away; separate preSerialization validation detected the deliberately invalid object. Projection and rejection are separate assertions. An initial probe error omitted required `run_id` and used non-contract error codes; serializer failures exposed this mistake, which was corrected to the actual Error schema before the measured passing run.
3. Real trusted HTTPS observed Secure/HttpOnly/SameSite=Strict/Path=/, no Domain, Max-Age and matching deletion attributes. No browser cookie-store behaviour is claimed. Origin/custom-header checks are a candidate policy, not an accepted production CSRF decision. Framework 413/415 behaviour remains a contract compatibility gap.
4. Real same-client transactions rolled back session insertion on illustrative audit failure and avoided committed audit on insert failure. Cancellation allowed successful rollback/reuse; terminated/failed-rollback clients were discarded; bounded pool exhaustion settled and later health recovered. Bigints above Number.MAX_SAFE_INTEGER survived pg/JSON as decimal strings. Audit examples are synthetic; no failed-login catalogue requirement is invented.
5. Actual PostgreSQL lock waits were observed before releasing barriers. Delayed-expired renewal failed, renewal did not decrease its deadline or extend the absolute cap, logout-first denied renewal and renewal-first was followed by denial after logout. These are repository results, not integrated HTTP/DB handler acceptance.
6. Clock backstep remains an observed failure of the simple candidate. Following the owner's explicit choice to harden detection/fail closed, a separate probe variant serializes a singleton persistent clock-health record, samples time after the relevant locks, and latches an observed regression. Issuance and authenticated checks/renewal then fail closed, including after a new repository instance and after wall time catches up. Logout can still revoke using the last recorded observation. Real DB-authority issue/check also survived a one-day skew of the application Date.now. This variant has an actual serial bottleneck. A separate operator-recovery candidate now checks attestation/preconditions, revokes all prior sessions and commits recovery audit with the clock-state reset; audit failure rolls everything back. No deployed or independently verified operator workflow is implied. It cannot detect a forward/backward interval without observations, prove elapsed time during outage, or establish DB restart behaviour. Its new table exists only in disposable probe SQL; no production migration or time guarantee is approved.

## Incomplete assertions and retained failures

The full per-ID/subtest ledger is result.json. Three Not run IDs are E-DB-05 (separate failed-login audit applicability), E-DB-10 and E-SESSION-14 (optional disabled-account comparison). Locked/disabled credentials remain part of TC-01 application acceptance and cannot be skipped by that laboratory applicability label. The final run added all eight historical schema-case mappings, malformed output, exact body boundaries, negative logout CSRF, HTTP no-cookie on real audit rollback, and an explicit fixation request. E-DB-09 exercised actual backend termination plus an injected post-COMMIT receipt failure: the caller retained an unknown outcome, discarded the connection, did not retry, and later observed the single committed row. That hook simulates receipt loss after an actual commit; no actual TCP acknowledgement drop or whole-container kill is claimed. E-SESSION-12 retains the baseline Run-failed guarantee despite passing guarded-variant tests. Scrypt measurements are synthetic work checks; no production security/capacity claim or constant-latency assertion is made.

Earlier attempts were not discarded: [restricted-environment measured failure](sp01-runtime-2026-10-28/prior-restricted-run/result.json) and [earlier measured passing subset](sp01-runtime-2026-10-28/prior-subset-run/result.json) retain their own inputs/logs. Before manifest-based execution, exploratory attempts encountered unavailable Docker, invalid Error payloads, missing TLS configuration, an idle-pool teardown error, and concurrent test fixtures sharing one environment file. These were corrected with exact Error mapping, explicit TLS configuration, pool end before container teardown, unique environment filenames and serial suite execution. Those earlier console-only attempts have no complete source snapshot and are not presented as reproducible measured results.
