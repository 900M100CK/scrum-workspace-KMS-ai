## 2. Recommended technical baseline

[ADR-0027](../../../adr/0027-task-creation-foundation.md) gives the exact protocol and rationale. This batch fixes the implementation seams and acceptance contract, rather than creating another mutable design/status registry.

- One Workspace owned client/transaction. Current auth_clock_state → actor account → session → Project guard → current membership/capability/outcome → final same-client session/time guard precedes first write/output. Detail uses an internal project-ID hint, then project lock and task re-read. New bulk writers would order tasks by ID after project; none are implemented now. Preserve clock-fault latching/typed denial and unknown-COMMIT semantics.
- Creation needs valid backlog-author, not membership-manage. Provisioning is private clock → target account → project/member/grant with expected revision/reason and co-committed private audit. Existing removal/rejoin invalidation already covers all individual grants; no revival/last-author exception is added.
- Append uses exact PostgreSQL max(current Backlog position)+1 under the project lock; empty starts 1. Let existing 003 trigger maintain generation; never increment it a second time. Task revision stays safe numeric, Backlog generation and position stay exact decimal strings. task_id is server UUID; initial state todo, assignee null, no blocker events, Backlog/null Sprint.
- With Q-02 selected, use a once-recorded DB-clock millisecond creation timestamp, immutable on Task and included in original Task output/audit. No old timestamp is fabricated. New 009 refuses unreconciled existing tasks, legacy createTask identities and pre-existing unprovenanced author grants before mutation. Down refuses retained task/outcome/author/audit data; empty-compatible reverse restores prior 008 constraints/functions only. Applied 001–008 remain untouched.
- With Q-03 selected, extend existing idempotency_record and its strict outcome/immutability constraints for createTask. result_ref is Task ID, not Project ID. A new tasks/outcomes.ts adapter gets project_id from validated snapshot and task_id from result_ref. Actor/operation/key PK is unchanged; hash covers createTask/project/type/exact valid title/description-default-empty. Current create authority and final guard precede original snapshot disclosure; later edits never reconstruct or mutate that snapshot.
- Reads require current membership and use current Task location plus highest committed blocker sequence, not role/create/audit-read. Hold project guard while taking current rows/generation/authority and recheck before output. Every supporting writer must cooperate with the same DB guard. This is not a protected socket/source-send claim.
- Reuse ProjectCursor unchanged with SACW_PROJECT_CURSOR_KEY, TTL 300, fixed internal page size 50 and task-list-v1 domain separation. SQL determines all-task ID order or exact numeric Backlog position/task-ID order. Bind actor/project/filter/order/limit/membership revision-generation/full ordered projection/backlog_revision. Decode the last Task UUID, find it in the same sorted projection, then slice after its index. Never use ID greater-than for position order; missing verified marker or stale/expired projection gives 409 without items. No public limit/cursor table/key ring or duplicate pure codec suite.
- Keep current no-store, strict serializer/validation and same-origin mutation protection. Reject blank-after-trim titles but preserve valid original title bytes for storage/hash; description omitted becomes empty. No arbitrary new title/description length policy beyond the selected existing 8192-byte JSON body pattern. Coordinated contract support adds POST 413/415 and detail GET 400 for extra selectors before enabling those outcomes. Unknown/nonmember/foreign reads retain exact generic 404; dependency faults remain generic 503.
- Advertise only actually registered task operations. Proposed internal seam: ProjectHttpOptions.taskOperations is a trusted optional readonly set of createTask/listTasks; WorkspaceProjectStore.actions accepts that set as a default-empty extra argument. buildApp passes TASK_OPERATIONS exported by the task HTTP module only when options.tasks exists. P04 exports createTask; P05 adds listTasks when its route exists. Current project-only fixtures remain empty/unchanged. Inside actions, current members get listTasks if registered; only current explicit authors get createTask. No client may supply this internal set, and it grants no mutation authority.

The full-read digest is a conservative current-pattern choice, explicitly unbenchmarked; it is not a scalability acceptance or a persisted-revision optimization. Same-actor new login alone does not invalidate a cursor. Content/state/blocker projection changes may invalidate a cursor without changing Backlog set/order generation; safe equality of these separate tokens is not interchangeable.
