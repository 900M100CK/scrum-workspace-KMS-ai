# Session HTTP operations

POST, GET and DELETE /session use the actual Workspace session store. UI/browser acceptance belongs to P11; no project/document capability or D-07 guard is granted by a session.

Configure both SACW_WORKSPACE_DATABASE_URL and SACW_SESSION_ORIGIN in the private server environment. The URL must name workspace_app in workspace_db, never an operator identity. Origin must be an HTTPS origin, such as https://localhost:5173. SESSION_IDLE_SECONDS / SESSION_ABSOLUTE_SECONDS retain the selected configurable starting values 1800 / 28800. Missing configuration leaves session routes explicitly unavailable (503); partial/invalid configuration stops startup. /healthz is process liveness only.

Use the P08 operator procedure to migrate approved storage, provision accounts and initialize clock state explicitly. Server startup never migrates, provisions or resets time. This task used only disposable test DBs. Run npm run dev:workspace, with the web [HTTPS/proxy setup](../../apps/web/LOCAL-HTTPS.md) for same-origin /api/session. The service itself binds loopback HTTP behind that TLS terminator; do not expose it directly as a production public HTTP endpoint. Browser code does not call Knowledge.

Sign-in accepts exactly username/password JSON. It requires the exact configured Origin plus X-SACW-Request: 1; missing/wrong values return 403. Non-mutating Ajv 2020 validation rejects extra fields, arrays/coercion, empty or wrong types. The JSON body bound is 8192 bytes (413); unsupported media types return 415. These transport statuses use the declared Error shape. No case folding, email alias or Unicode normalization is invented. NUL cannot represent a PostgreSQL username and follows the generic unknown-user/dummy-KDF path.

Wrong, unknown and manually disabled accounts receive the same 401 body after real or dummy KDF work. KDF saturation, clock/DB/audit failure and internal errors return generic 503. Only a verified current credential revision can issue a fresh token after known commit. Correlation comes from a server-generated request UUID, not a supplied request/actor header.

The __Host-sacw-session cookie is Secure, HttpOnly, SameSite=Strict, Path=/, with no Domain. Expires comes from the DB-derived effective deadline; The server does not calculate authorization or Max-Age from app wall time. JSON returns only user_id/expires_at. Final object validation runs at serialization, after preSerialization hooks, and rejects an invalid object rather than silently projecting away secret fields. On unsuccessful session responses the final onSend hook suppresses queued cookie-plugin output too. A post-commit output failure can leave an inaccessible retained row; no automatic retry or physical purge is implied.

GET /session uses exactly one correctly named cookie and current persistence state. Missing, duplicate, forged, old-name, expired, revoked or disabled state returns 401. Client query/body/actor/service headers do not establish identity. Request-local sessionContext is assigned only after a successful current lookup and is no grant of project/document authority. GET renews a strictly unexpired session and refreshes the same cookie. Effective expiry becomes min(absolute expiry, max(existing expiry, DB now + idle duration)); equality at either deadline is expired. Only an actual deadline increase increments revision and writes session_renewed audit. All session responses use no-store. Public authentication errors include required run_id:null and no internal cause.

Default logging remains disabled. The optional tested logger emits request method/request ID and response status/timing; it omits URL/query, headers, cookies and bodies, with additional redaction. Never log the internal store error cause. Error mapping exposes no stack, password, token, hash or DB detail.

Runtime packaging must retain contracts/openapi/workspace.openapi.json at the same repository-relative location for source and compiled service layouts; schema load/compile failure stops startup. Workspace owns exact Ajv/formats/cookie pins. No development-only root schema harness is imported by the application.

Run npm run test:session:http after generating local TLS material as documented by the web guide (the command builds Workspace first). It creates disposable PostgreSQL and exercises actual handlers, configured compiled-server startup and a client trusting the local public certificate. It does not skip required HTTPS, and it does not establish browser Secure-cookie storage/send behaviour. npm run test:session:storage remains the separate P08 regression. Run npm run test:session:lifecycle for P10 actual PostgreSQL lock, boundary, audit/failure and HTTPS logout checks. Test-only injected times are labelled separately; production has no injected-clock configuration. No real secrets should be command-line arguments or test fixtures.

DELETE requires the same exact Origin/custom-header protection and no body. It revokes only the presented current token and commits session_revoked audit before clearing the same Secure/HttpOnly/SameSite/Path cookie with an empty 204. Missing/malformed/unknown/expired/already revoked tokens are idempotent 204. Supplied bodies return 400, oversized JSON 413 and unsupported media 415. Audit/DB failure or unknown COMMIT returns 503 without cookie clearing or false logout confirmation; no automatic retry is performed. A fault-latched clock still permits audited revocation, but a missing/unreadable clock row for a known session denies. Revocation never clears clock health.

All lifecycle operations acquire clock, account, then session locks; decision time is sampled after locks. The singleton serializes these short DB transactions. No lock is held over HTTP/provider waits. A request authorized earlier may already be in flight when logout commits; current session checks are not the D-07 content-send guard. Migration 006 only widens audit actions; rollback refuses retained lifecycle audit. This work applied it only to disposable storage.
